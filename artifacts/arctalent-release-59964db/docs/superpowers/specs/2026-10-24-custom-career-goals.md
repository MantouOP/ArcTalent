# Custom career goals

The user wants to type their own destination and have analysis recommend real learning courses with direct links, rather than being restricted to six demo occupations.

Add an always-visible career-goal form on the pathway screen. A title and optional desired-work description produce editable skill targets. The user can add/remove targets and record specialist skills outside the catalogue before applying the destination. The resulting custom destination participates in the existing individual matching, scenario comparison, schedule, exports, chat and browser persistence. Keep the six curated occupations and existing SME allocation behavior.

Use the existing server-side RunPod integration for structured analysis when configured. Never allow the model to invent courses, provider URLs, official occupation facts or employment outcomes. Course identity always comes from the verified catalogue. Without a configured/available model, clearly label local skill matching and allow manual targets; unknown goals receive no fabricated requirements. Expose unsupported specialist needs. Ask the user about AI setup while completing independent implementation.

Extend the skill vocabulary with HTML/CSS, JavaScript and digital marketing, and add six checked public learning resources for those subjects plus Python, AI literacy and digital security. Maintain existing budgets, study capacities, funding filters, completion state, sources and honest uncovered gaps. Estimates remain estimates.

Custom requirements and a neutral exposure factor of 0.5 are planning assumptions. They are never represented as O*NET requirements. Raw user text remains canonical in all three interface languages. AI receives only the goal/desired-work text, not CVs, worker names or company data. Validate all stored/requested data, bound request sizes/time and reject stale responses when input changes. No new dependencies, provider account or paid resources.
